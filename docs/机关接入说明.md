# 配重平台与升降门接入说明

更新：2026-10-10。当前交付为可复用机关与独立白模试验场；正式地图到位后接入。

## 试玩

在 Godot 打开 `scenes/debug/mechanism_lab.tscn`，按 **F6** 运行当前场景。

1. 按 **E** 解锁本试验场的投掷能力。
2. 右键拿起地上的尸体，向左侧高处平台瞄准。
3. 长按右键显示轨迹，调整方向和力度，使落点靠近平台中央，松开投出。轨迹止于第一次碰撞，落地后仍可能滑动。
4. 尸体落稳后，平台变绿，右侧门升起。穿过门，到达绿色终点。
5. **R** 重置；**Esc** 使用现有暂停菜单。火把可用于测试燃烧尸体。

2026-10-16 已移除 G 键加金币及右上角调试提示，正式地图和各测试房均不再响应该快捷键。金币仍按现有规则手动存档。

试验场使用当前鼠尸体占位表现。E 解锁只存在于这个调试场景，不记作已购商品。Esc → 存档会保存金币及已经完全升起的保持开启门；回菜单载入或重新启动载入后返回白模房，门保持通行，尸体与免费 E 能力重新开始。R 仍是调试重置，不读取或覆盖磁盘存档。

正式地图的油 / 灵魂鸡蛋 / 棒球手套已购状态、两颗石头等级及整组藤蔓烧毁后的通路，与金币一起手动保存。新建游戏从关闭的门开始，保留旧磁盘存档；回菜单 / 退出不自动保存。

## 放进新地图

1. 在地图的玩法节点下实例化 `scenes/mechanisms/weight_platform.tscn` 和 `scenes/mechanisms/lift_gate.tscn`。可用一个共同的 `Node3D` 父节点整体移动、旋转。
2. **平台根节点原点是顶面中心**，平台实体向下延伸。调整 `platform_size`，将顶面放在希望尸体落到的位置。
3. **门根节点原点是关闭门的底部中心**。调整 `leaf_size` 匹配门洞；白模使用离地 0.02 米的小间隙。
4. 在门的 Inspector 中设置 `platform_path` 指向对应平台。同一平台可被多扇门分别引用。
5. 配置 `open_offset` 与 `move_speed`。位移沿门根节点的局部坐标，整体旋转后随之旋转；门扇与碰撞同步移动。
6. 检查门扇整段行程的空间、门洞通行碰撞、玩家投掷站位和尸体落地滑动。新房间的离房回收触发器继续按既有流程另行配置。
7. 需要保存永久开通状态的门设置唯一 `persistence_id`，例如 `world.cleaning.weight_gate`；同一逻辑关卡移植到新地图时保留编号，节点可改名、移动或旋转。不同门分别编号；留空不保存。

保持机关及父节点的缩放为 `(1, 1, 1)`，通过尺寸参数适配大小。高度和投掷距离属于关卡布局，应在正式地图中重新试玩。

## 可调参数与行为

| 场景 | 参数 | 默认值 / 含义 |
|---|---|---|
| 平台 | `platform_size` | `(3.2, 0.4, 2.6)`，宽 / 厚 / 深 |
| 平台 | `required_corpse_count` | 1，所需落稳尸体数量；按数量，不按重量 |
| 平台 | `settle_time` | 0.2 秒，连续满足支撑检测后才计入 |
| 平台 | `enabled` | 开启检测 |
| 门 | `platform_path` | 控制此门的平台，相对节点路径 |
| 门 | `leaf_size` | `(3, 3, 0.3)`，门扇宽 / 高 / 厚 |
| 门 | `open_offset` | `(0, 3.4, 0)`，相对关闭位置的局部位移 |
| 门 | `move_speed` | 2.5 米/秒，沿行程匀速移动 |
| 门 | `latch_open` | `true`，首次触发后保持开启 |
| 门 | `persistence_id` | 留空不保存；白模实例为 `lab.weight_gate` |
| 两者 | `show_placeholder` | 显示占位外观，换美术时可关闭 |

平台只计入当前 `Corpse` 的实体碰撞在台面上受到支撑、未被手持且落稳的尸体。玩家、商店商品、悬空尸体和快速飞过不触发。多个尸体分别计数；拿起、转移或烧毁会清除相应负载，尸体自身价值、重量和燃烧计时由原系统维护。

默认门首次触发后保持开启，适配离房自动回收。设 `latch_open = false` 时，尸体不足会关门，尸体重新落稳会再次开门。门在开 / 关运动前检测整个下一步行程，遇到玩家、尸体、怪物或地形会停住，障碍移开后继续；门初始重叠也会阻止运动。暂停冻结机关与尸体计时。

平台提供 `pressed_changed(pressed)`、`load_changed(corpse_count)`；门提供 `opened`、`closed`、`blocked_changed(blocked)`。开 / 关完成信号发出时，查询状态已更新。载入直接恢复物理开门位置，不重放 `opened`、破坏或奖励事件。独立机关逻辑没有当前地图路径或坐标依赖。

## 存档接入

v6 单存档位保存金币、原三件已购能力、不点金石头 / 点金石头各自等级、关卡入口及 `opened_gates` 中的永久开通编号，兼容 v1—v5。v1—v3 没有门的记录，载入默认门关闭；v4 保留已记录的门，两颗石头等级为 0；v5 保留不点金石头等级，点金石头为 0。部分烧毁、燃烧剩余时间、尚未完全升起的门、临时开关模式（`latch_open = false`）、平台负载与玩家位置均不保存。

编号使用 1—64 个小写字母、数字、点、下划线或横线；每个关卡最多记录 32 扇开通门。重复或无效编号会拒绝本次存档，并显示失败原因，旧档保留。新地图暂未放置的有效编号会保留，下次手动保存不会抹掉它们。

正式地图的整组藤蔓父节点接入 `scripts/elements/vine_gate.gd`，直接子节点放 `FlammableProp`，设置唯一编号；当前为 `world.cleaning.vines`。只有全部子藤蔓移除后才保存永久开通，恢复时移除实体与碰撞并同步原房间提示 / 刷新点。

存档入口由 `GameFlow.SAVE_LEVELS` 注册固定代号，当前为 `world` 与 `mechanism_lab`；换正式地图时保留逻辑入口与机关编号并更新对应场景路径。其他调试房仍沿用正式地图载入入口。新增机关沿用 `persistent_gates` 组及组件的四个接口：`get_persistence_id`、`is_persistently_open`、`can_restore_persistent_open`、`restore_persistent_open`。

## 替换美术

- 平台外观放在平台的 **`Visuals`** 下。
- 门扇外观放在门的 **`Leaf/Visuals`** 下，随 `Leaf` 一起移动。
- 关闭 `show_placeholder` 后添加正式模型或 2D 展示节点，逻辑和碰撞继续工作。
- 门框放在门扇的外部，与固定地形一起布置；平台、门框和门扇由美术分别交付，门扇能独立移动。
- 地图静态碰撞应保留真实门洞，门扇运动空间应畅通。可见尺寸与平台 / 门扇碰撞尺寸需要一起校准。

## 验证命令

`tests/run_mechanism_regression.gd` 覆盖实际抓取 / 投掷 / 平台接触 / 开门通行、门的两种模式、燃烧和转移清理、暂停、快速关门避障、提前进入终点、共同父节点平移 / 旋转、实例尺寸独立及替换占位外观。

```sh
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --log-file /tmp/mechanism.log --script res://tests/run_mechanism_regression.gd --fixed-fps 60
```

使用 `--fixed-fps 30` / `120` 检查其他渲染帧率。实际窗口截图和测试为开发验证，正式地图接入后仍需检查新的碰撞与投掷布局。

`tests/run_level_progress_regression.gd` 覆盖手动保存 / 菜单载入、两种门的实际通行、部分进度排除、旧档迁移、错误数据、原子写入失败、稳定编号迁移及未匹配编号保留。必须指定隔离目录，避免覆盖真实用户存档：

```sh
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --log-file /tmp/level_progress.log --script res://tests/run_level_progress_regression.gd --fixed-fps 60 -- --data-dir=/tmp/level_progress_test
```

分别以 `--phase=write_world` / `read_world` 或 `write_lab` / `read_lab` 在两次独立进程使用同一隔离目录，验证关闭游戏后的持久化。
