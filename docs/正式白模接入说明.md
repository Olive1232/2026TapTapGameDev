# main_world 场景与菜单接入说明

更新：2026-10-15。`scenes/rooms/main_world.tscn` 是当前正式游戏入口；`map_world` 已弃用。游戏名和主菜单标题继续留空。

## 原样模型与玩家

`MapScale/MapOrigin` 直接实例化 `assets/map_origin.glb`，原始网格、材质与导入配置保留。父节点 `MapScale` 沿用当前放大后的尺寸（源模型 × 15）；玩家挂在场景根下，保持原尺寸。两个原始网格各自配置静态三角网格碰撞，资源在 `resources/environment/main_world/`，开启双面碰撞并使用世界碰撞层 1。新场景不引用旧入口的裁切 / 补面环境。

源 GLB 的 SHA-256 为 `677077df7b4eb9fbce3c73c83f7aeff59c15d7abf93078ea76091862e345c94d`。玩家出生于主厅地面上方 `(-28.5, 3.44, -1.5)`，朝向主厅内部；相机、剑、抓取、脚步音效均复用现有玩家组件。

世界控制脚本为 `scripts/rooms/main_world.gd`。HUD 复用金币、准星、底部操作提示和新存档闪烁引导；场景退出时释放对象池引用。

## 全地图照明

`main_world` 根节点实例化 `scenes/environment/main_world_lighting.tscn`，灯光使用世界坐标，不继承模型的 15 倍缩放。环境资源独立放在 `resources/environment/main_world_environment.tres`，全场景只有一个 `WorldEnvironment`。

- `Cave`：主厅暖色主光、外围冷色补光和坑口聚光，突出地面及坑沿高差。
- `Shop`：西侧商店区域采用暖光，北侧入口及背面增加补光。
- `EntryRoom`、`CleaningRoom`、`DeepRoom`：分别覆盖东侧三个有顶板的房间，入口偏冷、中部中性、深处偏冷。
- `Gallery`、`Connections`：覆盖南侧回廊与房间连接处，照亮门洞、转角及路面。
- `Alcoves`：为岩块背面和边缘凹处配置柔和补光，保留遮挡处的明暗层次。

共 51 盏点光、1 盏坑口聚光和 1 盏方向光；其中 11 盏局部主光投射阴影，其余用于补光。局部灯光按距离淡出，阴影更早淡出；补光关闭高光，主光降低高光，减少白模墙面的亮斑。环境启用天空环境光、ACES 色调映射、SSAO、SSIL 与低密度雾。使用项目现有 Forward+ 渲染器，无需烘焙。

灯光独立于模型与碰撞，可展开 `WorldLighting` 按区域调整。原始 GLB、材质、模型变换和两份碰撞资源不因打光改变。通过实际窗口检查了 18 个区域视角及出生点的武器 / HUD 视角；这属于白模阶段照明，后续替换正式材质时需重新校准亮度与色温。

## 主菜单与游戏内菜单

项目仍由 `scenes/ui/main_menu.tscn` 启动。`GameFlow.GAME_SCENE` 和存档入口代号 `world` 均指向 `main_world.tscn`：

- 新建游戏进入新世界，重置本轮金币、升级、关卡记录和引导，不覆盖磁盘存档。
- 载入游戏进入新世界，从新出生点恢复金币、升级记录、机关记录与引导阶段。
- Esc 暂停，停止游戏物理与操作、显示鼠标；再次按 Esc 或点击“继续游戏”恢复。
- 暂停菜单包含继续游戏、存档、回到主菜单、游戏设置和退出游戏；打开时焦点位于继续按钮。
- 游戏设置包含全屏 / 窗口模式和鼠标灵敏度，调整立即生效并单独保存。退出设置页仍保持暂停。
- 暂停时可手动保存；失败会显示错误并保留上次存档。返回主菜单和退出游戏不自动保存。
- 恢复时清除未消费的视角位移，忽略恢复后首帧由菜单空格确认带来的跳跃，随后仍可正常跳跃。

按 F5 验证完整菜单流程；F6 可直接运行当前白模场景。窗口模式交由 Godot 原生切换，避免在 macOS 全屏动画期间额外修改窗口边框。

## 旧存档兼容

保留原 `world` 存档代号和 v7 文件格式，兼容 v1—v6。存档与设置继续沿用既有数据目录，不因游戏名未定或地图入口改名丢失数据。

`main_world` 当前具备原始模型、碰撞、玩家、HUD 和菜单。老鼠刷新点、商店、洞及机关还需按新场景逐项布置。本次没有重新引入旧入口的几何裁切和玩法布局。

没有商店 / 洞时，世界脚本完整保留旧档的四项已购能力与两项重复购买等级；剑油与棒球手套恢复到现有玩家，尚无实体目标的洞升级先保留记录。`LevelProgress` 保留尚未放置的机关编号，再次保存不会抹掉这些进度。旧档缺少引导阶段时默认为完成，不向老玩家补播。

玩家坐标、临时尸体、怪物和燃烧状态不保存，载入从出生点进入；暂停菜单已说明这一点。

## 验证

当前入口和菜单验收使用：

```sh
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --log-file /tmp/main_world.log --fixed-fps 60 --script res://tests/run_main_world_regression.gd -- --data-dir=/tmp/main_world_test
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --log-file /tmp/main_world_menu.log --fixed-fps 60 --script res://tests/run_menu_regression.gd -- --data-dir=/tmp/main_world_menu_test
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --log-file /tmp/main_world_onboarding.log --fixed-fps 60 --script res://tests/run_onboarding_regression.gd -- --data-dir=/tmp/main_world_onboarding_test
```

新世界专项覆盖原样模型、碰撞和玩家、v1—v7 旧档的金币精度、升级及未放置机关记录、暂停保存、新建重置与对象池清理。菜单专项通过真实按钮 / 键盘事件检查新建、载入、继续、设置、保存成功 / 失败、返回主菜单、最小窗口布局、鼠标捕获以及键盘确认不触发跳跃。`--phase=write/read/quit_main/quit_pause` 用于跨进程和真实退出；图形检查可去掉 `--headless` 并增加 `--capture-dir=/tmp/main_world_menu_captures`。

验证结果：新世界专项 84 项、菜单 78 项 headless / 87 项实际窗口、新手引导 59 项、结构 396 项（包含新增照明资源）、字体 80 项通过；跨进程写入 / 读取 3 + 6 项、主菜单 / 暂停菜单真实退出 3 + 5 项通过。打光完成后重跑新世界与结构专项，并检查实际 Forward+ 渲染窗口。测试存档和截图均写入 `/tmp`，不覆盖真实用户数据。

## 弃用入口

`scenes/rooms/map_world.tscn`、`scripts/rooms/map_world.gd`、`map_origin_geometry.tscn` 和 `bake_map_origin.gd` 保留为旧布局参考；主菜单与正式存档均不再进入该场景。旧地图几何 / 通路 / 商店专项描述的是旧布局，不能作为当前 `main_world` 已布置这些玩法的证明。后续制作直接编辑 `main_world`，保留用户要求的原始模型。
