# 关卡拖拽预制体

在 Godot 文件系统中打开 `res://scenes/prefabs/`，把 `.tscn` 文件拖入 `main_world` 的 3D 视图或场景树。

| 文件 | 用途 | 放置与配置 |
|---|---|---|
| `flammable_vines.tscn` | 可燃、可攀爬藤蔓 | 原点为底部中心；`Size` 调整尺寸，`Tint` 调整颜色，`Climbable` 开关攀爬，`Respawn Delay` 设置燃烧销毁后刷新的等待秒数（默认 0，永不刷新），编辑器中实时预览。 |
| `torch.tscn` | 持续燃烧的火把 | 原点放在地面；运行后可点燃已涂油的剑及接触的可燃物。 |
| `lift_gate.tscn` | 升降门 | 原点为门底中心；`Platform Path` 选择控制它的配重平台，`Leaf Size` 设置尺寸，`Open Offset` 设置升起方向及距离。 |
| `weight_platform.tscn` | 尸体配重平台 | 原点是顶面中心；`Platform Size` 设置尺寸，`Required Corpse Count` 设置需要几具尸体，默认 1 具。 |
| `rat_spawner.tscn` | 老鼠刷新点 | 原点放在地面稍上方；默认每 3 秒生成 1 只、最多存活 5 只、刷新半径 2 米。紫色标记运行时隐藏。 |

建议都拖到 `MainWorld` 根节点下，或根下新建的玩法分组中。`MapScale` 专门用于放大原始模型，把玩法预制体放到它下面会同时继承 15 倍缩放。

藤蔓的燃烧火焰会自动覆盖 `Size` 指定的宽高，燃烧中修改尺寸也会更新；节点或父级的 Transform 缩放只继承一次。大面积火焰共用实例网格和一盏灯，放大藤蔓后不必再手动扩大火焰。覆盖尺寸专项 44 项、既有元素流程 67 项检查通过，并已在实际游戏中检查大型藤蔓及燃烧中调整尺寸的画面。

选择藤蔓根节点，在检查器中设置 `Respawn Delay`：0 表示烧毁后永不刷新；例如 5 表示完全烧毁后再等 5 秒，在原位恢复原尺寸、颜色、碰撞和攀爬能力，并可以再次点燃。等待期间不阻挡通路、不传火，暂停游戏时冻结刷新倒计时。此时间不包含 `ElementComponent/Burn Duration` 指定的燃烧过程；重新载入场景仍按关卡初始配置生成藤蔓。

玩家已移除跳跃操作。面向藤蔓靠近后按 **W** 自动开始攀爬；攀爬时 **W / S** 上下、**A / D** 横移，松开移动键悬挂，**E** 松开恢复下落。攀到顶沿后持续 W 会通过真实碰撞移动跨上平台；天花板仍阻挡攀爬。按 E 后须松开 W 再按，才会重新抓住藤蔓。负重会降低攀爬速度，底部文字显示当前攀爬操作。藤蔓烧毁、关闭 `Climbable` 或移出藤蔓范围时自动脱离；草不参与攀爬。空格继续用于菜单确认。

攀爬专项 23 项、菜单 78 项、新手提示 59 项、元素 67 项、正式洞 41 项检查通过；正式地图中的 `FlammableVines` 已用真实移动输入验证上爬与提示显示。

升降门和平台可以分别移动。选择门，在检查器中把 `Platform Path` 指向已放好的平台即可联动；门上方要留出升起空间。默认第一次开门后保持开启。需要保存开门状态时，填写唯一的 `Persistence Id`（例如 `world.room_1.gate_1`）；多个门不要使用相同编号。单片藤蔓默认重新载入时恢复，永久烧毁通路可另外使用 `vine_gate.gd` 分组管理。

这些文件是现有组件的独立拖拽入口，继续继承原有逻辑；老鼠刷新点已指定 `monster_rat.tres`。调整某个地图实例的参数即可定制该处玩法。

裂隙吊桥使用 `scenes/mechanisms/drawbridge.tscn`：原点是近岸铰链，放下后沿本地 -Z 方向延伸。默认竖起，烧断连接地锚的绳索后放平；`Deck Size` 设置桥面宽、厚、长，`Lower Duration` 设置落桥时间，`Persistence Id` 填写唯一编号后，手动存档会保存断绳状态。正式场景的两座桥集中配置在 `scenes/environment/main_world_drawbridges.tscn`。

## 商店内容

优先拖入 `shop_fixture.tscn`：包含六种商品货架、交付台面、店长、强化隔间和灯光，复用已有商店交易逻辑。原点放在地面，整体约宽 6.8 米、深 11 米，不含地板和建筑外壳。让商店与 `Player`、`Hole` 同级即可使用默认路径；放在分组下面时，在检查器中重新指定 `Player Path` 和 `Hole Path`。不要放到 `MapScale` 下。

| 文件 | 内容 |
|---|---|
| `shop_fixture.tscn` | 整套六商品商店，建议从这里开始摆放。 |
| `shop_shelf_oil.tscn` | 油货架，默认 5 金币，给剑涂油。 |
| `shop_shelf_corpse_value.tscn` | 不点金石头货架，10 金币起，每次涨 5；提高尸体价值。 |
| `shop_shelf_golden_coin.tscn` | 点金石头货架，10 金币起，每次涨 5；提高点金概率，最多 20 级。 |
| `shop_shelf_mirror.tscn` | 镜子货架，默认 200 金币，尸体入洞价值翻倍。 |
| `shop_shelf_corpse_return.tscn` | 灵魂鸡蛋货架，默认 5 金币，离房时遗留尸体自动入洞；需洞配置尸体出口、关卡配置房间离开触发器。 |
| `shop_shelf_charged_throw.tscn` | 棒球手套货架，默认 200 金币，解锁尸体蓄力投掷。 |
| `shop_counter.tscn` | 单格交付台面，`Socket` 为商品吸附位置。 |
| `shopkeeper.tscn` | 可被剑命中的店长。 |
| `shop_booth.tscn` | 强化隔间、帘幕和预览剑；原点沿用商店布局中心，隔间位于本地负 Z 方向。 |

运行后货架会生成实体商品和更新价格文字。购买流程为：右键拿商品 → 带到台面前右键放下 → 左键挥剑命中店长 → 动画结束后扣款并交付。

当前 `main_world` 已支持独立摆放的部件：世界脚本运行时创建 `ShopController`，连接根节点下的 `Shopkeeper`、`Counter`、`Booth`、`Shelf` 及另外五种商品货架，保持它们的父节点、位置、旋转和缩放。购买反馈接入底部文字，成功交付的能力和等级接入现有手动存档。修改这些节点名后，也要更新世界脚本中的路径。其他关卡独立摆放部件时，同样需要配置商店控制器的 `Counter Path`、`Shopkeeper Path`、`Booth Path`、`Shelf Path` 和 `Shelf Paths`。

调整整套商店布局时，右键实例选择“可编辑子节点”，再移动货架、`Counter` 或 `Shopkeeper`。增加商品货架时，把货架作为 `ShopRoom` 的直接子节点，控制器会在运行开始时收集它。替换台面、店长和隔间时保留节点名 `Counter`、`Shopkeeper`、`Booth`，并保留 `Booth/Curtain`、`Booth/PreviewSword` 及其内部节点；这些路径供交易和动画使用。隔间里的帘幕和预览剑使用现有动画坐标，建议随整套商店一起移动。

货架的 `Item Data` 指向 `resources/shop/` 中的现有商品配置。修改共享资源会影响所有引用它的货架；只修改一处时先将资源设为独立。六种效果沿用现有实现，预制体未新增商品规则。

`main_world` 的灵魂鸡蛋仍需单独接入尸体出口及房间触发器；未配置时购买会显示“尸体出口尚未配置”，不扣款、不消耗商品。旧档中这项能力的购买记录继续保留。正式世界的购买回归为 `tests/run_main_world_shop_regression.gd`。
